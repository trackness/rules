# Conventional Commits messages

Makes git reject a commit Claude makes with `git commit` or `git merge` whose message does not follow [Conventional Commits 1.0.0](https://www.conventionalcommits.org/en/v1.0.0/), with this message:

> Rejected: the commit message does not follow Conventional Commits. Start it with `<type>[optional scope][!]: <description>`, with type feat, fix, docs, style, refactor, perf, test, build, ci or chore, and leave a blank line before any body.

When a session starts, the script adds `GIT_CONFIG_*` variables to the session's environment that register it as git's `commit-msg` hook. Git then checks the final message of every commit that `git commit` or `git merge` makes through Claude's Bash commands, however the message was given (`-m`, `-F`, a heredoc or `--amend`), and still runs the repository's own `commit-msg` hook after it. Nothing is installed in any repository or git config, so commits made outside Claude are not checked. The type must be one of the ten above, in lowercase. A `git commit --fixup`, `--squash` or `--fixup=amend:` message, which puts `fixup! `, `squash! ` or `amend! ` before the target commit's subject, is accepted when what follows the prefixes is a conventional header.

Not checked: `git commit --no-verify` and `git merge --no-verify`, which skip the `commit-msg` hook; a git command that turns the hook off, such as with `-c hook.conventional-commits.enabled=false` or with `-c hook.conventional-commits.event=`, which empties its list of events, or that runs without the session's `GIT_CONFIG_*` variables or with them changed, such as under `GIT_CONFIG_COUNT=0` or `env -i`; a repository or user whose git config sets `hook.conventional-commits.enabled` to `false`, which turns the hook off for every later commit there; commits that other git commands make, such as `git revert`, `git cherry-pick` or `git commit-tree`, which run no `commit-msg` hook; commits made with a git older than 2.54.0, the first release with hooks defined in config; and commits that PowerShell commands make, since the lines the script adds are not plain assignments, so Claude Code gives PowerShell commands none of the session's `CLAUDE_ENV_FILE` variables, from this hook or any other. On Windows without Git Bash, Claude Code has no Bash tool, only PowerShell, and runs the `SessionStart` hook in PowerShell with no `CLAUDE_ENV_FILE` to register the hook in; the hook's command, written for a POSIX shell, may not run there at all, and if it does, the script tells Claude at session start that the check is not active.

Git checks the message it is about to record, so however a `git commit` or `git merge` gives the message, the check sees it, unless the hook is skipped or turned off in one of the ways listed above. The check stays inside Claude's sessions.
